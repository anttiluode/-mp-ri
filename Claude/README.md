# Claude branch + Gemini follow-ons

This directory is intentionally kept outside the core `mpri` package so experiment provenance stays visible.

The original solver, additivity experiment, and XOR branch were written by Claude. Two later files in the same folder — `ns_operator.py` and `run_clean_assosciative_memory.py` — are Gemini proposals that push the same substrate toward a self-writing fluid operator.

## Claude files

- `ns_core.py` — 64×64 periodic pseudo-spectral 2-D Navier–Stokes/vorticity solver with ETD-RK2 time stepping.
- `setup_geom.py` — fixed background geometry: two counter-rotating vortices create a shear channel, with two input sites and one downstream probe.
- `run_additivity.py` — runs `base`, `A`, `B`, and `AB` while sweeping input separation; compares raw downstream vectors `dAB` and `dA + dB`.
- `Run_xor.py` — generates 88 jittered trials (22 per bit pair), injects bits as signed vortex packets, evolves the fluid, and stores a 13×13 downstream patch.
- `eval_xor.py` — linear logistic-regression readout on raw bits, full flow patch, and a two-feature summary.
- `xor_data.npz` — stored dataset generated by `Run_xor.py`.

## Gemini file: `ns_operator.py`

This adds an explicit spectral split

```text
Omega_slow : |k| <= k_split     persistent operator / memory
w_fast     : |k| >  k_split     transient activations
```

and computes the low-pass projection of the fast-fast vorticity-advection term as a candidate Reynolds-stress transfer channel. The proposed experiment injects two high-frequency localized packets into a slow vortex dipole, evolves the full field, and measures low-frequency change plus high-frequency cleanup.

The idea is directly relevant to the recent OpenAI-inspired framing: fast packets should interact, transfer selected structure into slower modes, then disappear into the viscous sink.

**Current limitation:** the script compares the final slow field directly with the initial slow field. That mixes true fast→slow transfer with ordinary background evolution and diffusion. Localized carrier envelopes can also contain low-`k` sidebands from the start. A controlled receipt needs a no-pulse reference and, for collision-specific writing, the low-pass residual

```text
P_slow[omega_AB - omega_A - omega_B + omega_0]
```

after a washout period. `measure_reynolds_stress_transfer()` is the most interesting diagnostic in the file, but `run_plasticity_test()` does not yet use it to isolate the claimed write.

## Gemini file: `run_clean_assosciative_memory.py`

This asks a stronger functional question. It settles a two-vortex background, measures how strongly cue A perturbs detector B, repeatedly trains with A+B co-occurrence, waits between cycles, then tests A alone on the changed field.

That is an associative-routing experiment: the target phenomenon is not simply nonlinear feature expansion, but **a changed route caused by previous co-occurrence**.

The recall probe already subtracts a separately evolved clean background at every step, which is a good design choice.

The remaining decisive controls are:

- sham training for the same elapsed physical time;
- A-only training;
- B-only training;
- non-overlapping or phase-scrambled A+B training;
- an explicit fast-mode washout criterion before recall;
- record both detector A and detector B, not only B, plus peak timing.

Without those controls, a routing gain could still come from ordinary aging of the vortex background, residual fast activity, or generic repeated-pulse deformation rather than associative co-occurrence.

## Running

Claude XOR branch:

```bash
python Run_xor.py
python eval_xor.py
```

`eval_xor.py` needs `scikit-learn` in addition to NumPy. The stored `xor_data.npz` lets the evaluator run without regenerating the fluid trials.

Claude additivity sweep:

```bash
python run_additivity.py
```

Gemini probes:

```bash
python ns_operator.py
python run_clean_assosciative_memory.py
```

The Gemini scripts should currently be treated as **experimental proposals, not positive receipts**, until the matched controls above are run.
